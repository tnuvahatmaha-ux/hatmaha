# המטמיעון

מערכת לניהול מחזור החיים של צוות הטמעה: קליטה, שיוך מקצועי, הכשרות ותרגולים,
זמינות ואילוצים, שיבוץ לאתרי Go Live, אישורים, תקשורת ודיווח.

בנויה לפי האפיון הרשמי (גרסה 1.1), ומיישמת את קריטריוני הקבלה AC-01 עד AC-14.

---

## מה מיוחד כאן

**שני מנועים מונעי-דאטה.** מנהל ההטמעה משנה הרשאות וחוקי עבודה מתוך הממשק,
בלי פיתוח ובלי פריסה מחדש:

- **מנוע הרשאות** — RBAC של ארבעה תפקידי בסיס, ומעליו הרשאות פרטניות שמרחיבות
  או מצמצמות כל תפקיד, עם Scope (מערכת / אתר / תחום / תת-קטגוריה / משויכים /
  מידע אישי) ועם תוקף. שלילה מפורשת גוברת על היתר, ואין הרשאה משתמעת.
- **מנוע חוקיות** — 15 סוגי תנאים פרמטריים (חפיפות, שעות, מנוחה, הסמכות, כיסוי
  משמרות, מינימום משמרות זמינות לפי סוג ועוד). כל חוק מוגדר ברמת מערכת, אתר, תחום, תת-קטגוריה או משתמש, עם
  חומרה: אזהרה, דורש אישור, או חוסם.

**חריגה שדורשת אישור אינה מבוצעת ומגולגלת אחורה — היא כלל אינה מבוצעת.**
הפעולה נשמרת כ-JSON בעמודת `pending_action`, ומשוחזרת רק אחרי שהמאשר הכריע,
ואחרי בדיקה חוזרת שהיא עדיין חוקית.

**כללים קריטיים נאכפים במסד ולא בקוד האפליקציה.** גרסת סידור שפורסמה אינה ניתנת
לשינוי, חפיפות נחסמות, ומדריך ראשי אחד בכל רגע — הכול דרך טריגרים ומגבלות
`EXCLUDE`, כך שאי אפשר לעקוף אותם מאף נתיב.

**שלבי אתר.** כל אתר עובר הכשרה ← עלייה לאוויר ← ליווי. מיקום יכול להתקיים רק
בחלק מהשלבים, ומשמרת יכולה להיות מוגדרת לשלב מסוים. השלב של כל יום נגזר ממועדי
השלבים של האתר (או מתאריך העלייה לאוויר), ולכן הסידור והגשת הזמינות מחליפים מיקומים
ושעות לבד — גם באמצע שבוע.

**מאגר מיקומים.** כל מיקום שמוקם באתר נשמר במאגר משותף, ומופיע ברשימה בהקמת האתר
הבא — יחד עם המשמרות שהוגדרו לו.

**הודעות לצוות.** מדריך שולח הודעה ונהלים לצוות שלו, עם קבצים מצורפים (Supabase
Storage) ובקשת אישור קריאה, ורואה מי קרא ומי אישר.

## הסטאק

| שכבה | טכנולוגיה | פריסה |
|---|---|---|
| לקוח | React 18 + Vite + React Router | Render — מוגש מהשרת |
| שרת | Node.js + Express 5 (ESM, ללא build) | Render (חבילה חינמית) |
| מסד נתונים | PostgreSQL של Supabase | Supabase (חבילה חינמית) |
| אימות | Supabase Auth — דוא״ל וסיסמה | Supabase |

הכול עובד בחבילות החינמיות, ללא כרטיס אשראי.

**הלקוח והשרת רצים כשירות אחד.** בייצור Express מגיש את `client/dist`, כך שיש
כתובת אחת, בלי CORS ובלי שירות אירוח נוסף. בפיתוח הם רצים בנפרד כרגיל.

### שתי החלטות שכדאי להכיר

**השרת מתחבר ישירות ל-Postgres, לא דרך PostgREST.** המערכת נשענת על טרנזקציות
מרובות משפטים (פרסום סידור, שחזור פעולה שאושרה), על `set local app.actor_id`
כדי שיומן הביקורת יידע מי האדם מאחורי החיבור, ועל שגיאות `EXCLUDE` מלאות כדי
למפות אותן להודעה בעברית. הלקוח משתמש ב-`@supabase/supabase-js` לאימות בלבד.

**אכיפת ההרשאות היא בשרת; RLS היא שכבה שנייה.** המערכת חוצת-משתמשים מעצם טבעה
(מנהל הטמעה רואה את כולם), ולכן כל שאילתה מסוננת לפי ה-Scope האפקטיבי שחושב
עבור `req.user.id`. RLS מוגדרת deny-by-default: אם ה-anon key ידלוף, מחזיק טוקן
לא יוכל לקרוא דבר מלבד השורות שלו עצמו.

## מבנה המאגר

```
├─ client/              React + Vite
│  ├─ src/
│  │  ├─ lib/           api.js (הנתיב היחיד לשרת) · time/format · useApi
│  │  ├─ context/       Auth · Permissions · Toast
│  │  ├─ components/    ui/ (כולל StateView) · layout/
│  │  └─ pages/         מסכים, ו-settings/ עם הטאבים
│  ├─ tests/            בדיקת רינדור לכל מסך
│  └─ public/_redirects לא בשימוש ב-Render (השרת מטפל בניתוב SPA); נשאר לאירוח סטטי
│
├─ server/              Node + Express
│  ├─ src/
│  │  ├─ permissions/   engine.js — מנוע ההרשאות
│  │  ├─ rules/         engine.js · conditions/ (15 קבצים) · exceptions.js · actions.js
│  │  ├─ services/      כל הלוגיקה העסקית
│  │  ├─ routes/        ראוטר לכל קבוצת API
│  │  ├─ middleware/    requireAuth · requirePermission · validate · errorHandler
│  │  └─ lib/           db · time · errors · etag · idempotency · csv
│  └─ tests/            יחידה + אינטגרציה מול Postgres אמיתי
│
└─ supabase/
   ├─ migrations/       0001–0020, מורצות לפי הסדר
   └─ tests/            בדיקת RLS + סקריפט הרצה מקומי
```

### אינווריאנטים שהמבנה אוכף

- ראוטר לא נוגע ב-Supabase; service לא קורא `req`.
- מנוע החוקיות לא כותב דבר מלבד דרך `rules/exceptions.js`.
- **`server/src/lib/time.js` הוא המודול היחיד שממיר בין זמן מקומי ל-UTC** — כך
  באג משמרת הלילה לא יכול לחזור דרך call-site חדש.
- `requirePermission` הוא middleware ולא קריאה בתוך handler, ובדיקת
  `tests/route-coverage.test.js` נכשלת על כל נתיב שנכתב בלי אכיפה.

## הרצה מקומית

### דרישות מקדימות

- Node.js 22 ומעלה
- פרויקט Supabase (חינמי), או PostgreSQL מקומי לפיתוח

### 1. התקנה

```bash
npm run install:all
```

### 2. מסד הנתונים

ב-Supabase: SQL Editor ← הרצת קבצי `supabase/migrations/` **לפי הסדר**, מ-0001 ועד 0020.

לפיתוח מול Postgres מקומי:

```bash
./supabase/tests/run_local.sh
```

הסקריפט יוצר מסד נקי, מריץ את כל המיגרציות, ומריץ את בדיקות ה-RLS.

### 3. משתני סביבה

```bash
cp server/.env.example server/.env
cp client/.env.example client/.env
```

מלא/י את הערכים לפי ההסברים שבתוך הקבצים. איפה מוצאים כל מפתח — מתואר ב-`DEPLOY.md`.

### 4. הרצה

```bash
npm run dev:server
```

```bash
npm run dev:client
```

הלקוח יעלה ב-<http://localhost:5173> והשרת ב-<http://localhost:8080>.

### 5. המשתמש הראשון

**המשתמש הראשון שנרשם למערכת נהיה מנהל הטמעה אוטומטית.** אין צורך לערוך SQL
ידנית. מכאן ואילך, כל משתמש נוסף מקבל את תפקידו מההזמנה שהמנהל יוצר במסך
"מטמיעים".

### הדרך המהירה: מצב פיתוח מקומי, בלי Supabase

כדי לראות את המערכת עובדת בלי להקים פרויקט Supabase, יש מצב התחברות מקומי עם
נתוני דמו: 8 משתמשים בכל ארבעת התפקידים, שני אתרים עם משמרות (כולל משמרת לילה),
סידור שפורסם לשבוע הנוכחי וטיוטה לשבוע הבא, הגשות זמינות, בקשות, וחריגה שממתינה
לאישור.

ב-`server/.env` מגדירים `AUTH_MODE=local`, וב-`client/.env` מגדירים `VITE_AUTH_MODE=local`.
אחר כך:

```bash
npm run db:start
```

```bash
npm run dev:server
```

```bash
npm run dev:client
```

במסך הכניסה בוחרים משתמש ונכנסים בלי סיסמה. הכפתור "כניסה כמשתמש אחר" מאפשר
לראות את אותה המערכת מנקודת המבט של מנהל, מדריך, מוביל או מטמיע.
לאיפוס המסד לנתוני הדמו המקוריים:

```bash
npm run db:reset
```

**ההגנות על המצב הזה.** רק ההזדהות מקוצרת; ההרשאות, החוקים ויומן הביקורת פועלים
כמו בייצור. כדי שהמצב לא יופעל בייצור בטעות, הוא מוגבל בשלוש שכבות:

- השרת מסרב לעלות עם `AUTH_MODE=local` כש-`NODE_ENV=production`.
- במצב הזה השרת מאזין רק ל-`127.0.0.1` ולא לרשת.
- הלקוח מפעיל את המצב רק בשרת הפיתוח של Vite. בבנייה לייצור הקוד שלו מוסר
  מהחבילה לגמרי, גם אם המשתנה הוגדר בטעות.

נתוני הדמו נמצאים ב-`supabase/dev/seed_demo.sql`, מחוץ לתיקיית המיגרציות, והקובץ
מסרב לרוץ מול פרויקט Supabase אמיתי.

## בדיקות

```bash
npm test
```

מריץ את בדיקות השרת. בדיקות האינטגרציה דורשות Postgres מקומי — בלעדיו הן מדלגות
על עצמן ולא נכשלות.

```bash
npm --prefix client test
```

מריץ בדיקת רינדור לכל מסך: מוודא שאף מסך אינו נופל בזמן ריצה, ושמצבי הטעינה,
הריק, השגיאה וחוסר ההרשאה קיימים בכולם.

```bash
./supabase/tests/run_local.sh
```

מריץ את כל המיגרציות על מסד נקי, ואז את בדיקות ה-RLS שמוכיחות ש-anon key דלוף
אינו חושף מידע.

### מה הבדיקות מכסות

| תחום | מה נבדק |
|---|---|
| זמן | המרות אזור זמן, מעבר שעון קיץ, ומשמרת לילה שחוצה חצות |
| מנוע הרשאות | Deny גובר, Manage מספק כל פעולה, כל סוג Scope, פקיעה, ומטריצה אפקטיבית |
| מנוע חוקיות | כל 14 סוגי התנאים, כפונקציות טהורות |
| הרשאות מקצה לקצה | AC-01 עד AC-04 מול מסד אמיתי |
| בקשות ואילוצים | AC-09, AC-10, AC-11 — כולל שחריגה אינה נכנסת לתוקף לפני החלטה |
| סידור עבודה | AC-12, חסימת חפיפות לילה, ואי-אפשרות לשנות גרסה שפורסמה |
| RLS | AC-13 — משתמש רואה רק את השורות שלו, ו-16 טבלאות חסומות לגמרי |
| כיסוי נתיבים | כל נתיב תחת `/api` אוכף הרשאה, או פועל רק על המשתמש עצמו |

## חמישה באגים מהפרוטוטייפ שתוקנו בתכנון

| הבאג | התיקון, וברמה שבה הוא יושב |
|---|---|
| השוואת "דקות מחצות" גרמה לכך שמשמרת 22:00–06:00 נתנה `1320 < 360` → false, וכל חפיפת לילה התפספסה | שתי שכבות: `tstzrange` + `EXCLUDE` במסד, ו-`toInstants()` בקוד — במודול זמן יחיד |
| סריקת התנגשויות התעלמה מ-`version_id`, אז טיוטה "התנגשה" עם העותק שלה שפורסם | כל שאילתת קונפליקט ממודרת לפי גרסה, וכך גם ה-`EXCLUDE` |
| שורות שפורסמו סומנו "לקריאה בלבד" אך לא הוגנו בקוד | טריגר `ROSTER_VERSION_READ_ONLY` במסד — לא ניתן לעקוף מאף נתיב |
| מטמיע רב-אתרי נחתך ב-`[0]` בניתוב אילוצים, במכסות ובמשמרות | שום דבר בסכמה אינו ניתן ל-`[0]`; ריבוי אתרים מחייב בחירה מפורשת |
| הגשת זמינות חוזרת דרסה בשקט החלטת מנהל | הצהרה שהוכרעה היא immutable; הגשה חוזרת = `revision+1`, וההיסטוריה שורדת |
